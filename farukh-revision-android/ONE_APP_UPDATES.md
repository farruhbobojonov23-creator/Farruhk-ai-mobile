# FARUKH REVISION PRO — одно приложение, обновления внутри
Дата: 2026-11-23. Production package ID: `com.farukh.revision`.
Native version 0.5.0 (versionCode 21). Не путать с разовыми `.preview.test` и `.preview.test044`!

## 1. Ежедневное обновление интерфейса
- В «Настройки и облако» нажать «Обновить приложение».
- Приложение сначала проверяет подписанную APK на `https://farukh-revision-updates.onrender.com/revision-app/latest.json`.
- Если новой APK нет, проверяет актуальный `https://more-sushi-studio.onrender.com/revision.html` через native bridge `refreshWebUi()` и подгружает HTML.
- Транспорт — HTTPS к фиксированному хосту, без произвольных редиректов, с таймаутами и ограничением размера.
- Проверяются обязательные структурные элементы UI и SHA-256. HTML сохраняется во внутренний кеш атомарно.
- WebView продолжает использовать `https://appassets.androidplatform.net/` как базовый origin — localStorage и сохранённые ревизии не теряются при перезагрузке интерфейса.
- При отсутствии сети используется последний локальный HTML или встроенная копия APK. Переключение экрана и печать остаются доступны без обновления.
- Незавершённая ревизия сохраняется через `rev040Snapshot()` до замены HTML.
- Кнопка «Эффекты» должна воспроизводить заставку внутри WebView, не открывая внешний браузер.

## 2. Новая версия Android-оболочки
При изменении кода Java/разрешений/иконки нужно **реальное обновление APK**:
- Тот же `applicationId`: `com.farukh.revision`.
- Тот же постоянный PKCS12 сертификат (его fingerprint ниже).
- Только строго увеличивающийся `versionCode`.
- Через `PackageInstaller` с подтверждением Android, проверкой SHA-256, пакета и совпадения подписанта.
- Нельзя автоматически установить чужую/debug-подписанную APK поверх стабильной.
- Сервисы обновлений на Render используют отдельную ветку `feature/farukh-revision-updater-20261122` и не заменяют другие проекты.

## 3. Одноразовая настройка защищённой подписи GitHub Actions
В GitHub → Settings → Secrets and variables → Actions → Repository secrets требуется задать:
- `FARUKH_REVISION_KEYSTORE_BASE64`: base64 содержимого приватного файла PKCS12.
- `FARUKH_REVISION_KEYSTORE_PASSWORD`: пароль этого файла.
- `FARUKH_REVISION_KEY_ALIAS`: `farukh-revision-production`.

Секреты нельзя коммитить в публичный репозиторий. Не пересоздавать ключ при обновлениях.
Workflow `.github/workflows/farukh-revision-signed-release.yml` собирает APK, подписывает через Android SDK apksigner, проверяет сертификат и versionCode, затем **одним коммитом** публикует `farukh-revision-update-server/releases/revision-pro.apk` и `release.json`.
Render autoDeploy открывает новую APK по постоянному адресу для кнопки обновления. Если секреты не заданы — публикация пропускается; не выдавать debug APK за обновление.

## 4. Миграция с тестовых APK
Старые `com.farukh.revision.preview.test`, `com.farukh.revision.preview.test044` подписаны одноразовым debug-ключом, поэтому обновление поверх них без оригинального ключа невозможно.
- Не удалять старые тестовые версии до резервной копии и проверки истории.
- Если есть данные, сначала войти в облако в старой версии, выполнить синхронизацию и убедиться, что история отображается. На стабильной войти в тот же аккаунт и проверить данные.
- Локальные базы разных applicationId не переносятся автоматически из-за Android sandbox.
- Только после проверки миграции удалить старые тестовые версии и использовать одно приложение `FARUKH REVISION PRO`.

## 5. Чек-лист устройства
1. Установить единожды стабильную, подписанную APK.
2. Проверить иконку F, заставку, отображение трёх действий над нижним меню и работу 4 разделов.
3. Сохранить тестовую ревизию, закрыть и открыть приложение — данные сохранились.
4. Обновить текст UI на сайте, нажать «Обновить приложение» — без скачивания APK меняется только интерфейс, данные остаются.
5. Выключить сеть: приложение стартует из кэша.
6. При выпуске новой APK с тем же ключом проверить обновление по кнопке с подтверждением Android.
