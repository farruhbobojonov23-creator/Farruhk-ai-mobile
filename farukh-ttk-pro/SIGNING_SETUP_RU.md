# FARUKH TTK PRO — подписанные Android-обновления

## Правило безопасности
**Никогда не добавляйте ключ (.p12/.jks), пароль и base64 ключа в GitHub-репозиторий, комментарии или переписку команды.** Эти значения должны храниться только в GitHub Actions Secrets и резервной копии, доступной владельцу.

## Почему предыдущий APK не обновляется
Проверенные SHA-256 сертификаты:
- APK Premium 0.4: `3ce2960ae17b9e775146036df87e2bca7575eb16b54ca58c535d47b790bf526d`
- APK Japanese Pro 0.5: `e4055ce2ed53065810f2cc371489a37353737801c0d076b4d0068362d960b00d`

Это **разные сертификаты**, хотя packageId одинаковый. Android запрещает устанавливать один поверх другого. По этой причине старые данные нельзя подвергать риску: сначала сделайте проверенную резервную копию через приложение, затем выполняйте одну контролируемую миграцию на новую постоянную подпись.

## Постоянная подпись для всех новых версий
Для продакшена создан отдельный долгосрочный ключ:
Сертификат SHA-256: `39952072751769b615811add7a4384025c0dc937f7a354a21d57cee2e33ab6fb`.

Файл ключа хранится только в личном защищённом ZIP владельца, а **не** в репозитории.

В Settings → Secrets and variables → Actions → New repository secret владельцу необходимо создать пять секретов:

1. `FARUKH_TTK_KEYSTORE_B64` — base64 содержимое ключа .p12.
2. `FARUKH_TTK_STORE_PASSWORD` — пароль хранилища.
3. `FARUKH_TTK_KEY_ALIAS` — имя ключа.
4. `FARUKH_TTK_KEY_PASSWORD` — пароль ключа.
5. `FARUKH_TTK_CERT_SHA256` — SHA-256 сертификата выше.

Готовые значения находятся в личном защищённом архиве, который нельзя публиковать.

### Проверка перед выпуском
1. Дождаться успешной сборки APK и эмуляторного теста на **одном SHA**.
2. Запустить `FARUKH TTK PRO Stable Signed Release` вручную на ветке `farukh-ttk-pro`.
3. Workflow проверит пять секретов, прогон эмулятора, подпишет APK новым постоянным ключом, сверит сертификат и опубликует релиз GitHub.
4. Только успешный подписанный выпуск получает публичный HTTPS URL в `farukh-ttk-pro/updates/latest.json`.
5. Пользователь установленной **стабильной** версии получает уведомление об обновлении; Android устанавливает новый APK поверх старого при совпадении подписи и увеличенном versionCode.

Важно: бесплатный GitHub Actions не гарантирует доступность квот в будущем, а ранние APK, подписанные другими ключами, не совместимы с этой новой стабильной цепочкой.

## Google Drive
Приложение может автоматически записывать PDF и резервную JSON-базу в папку, которую пользователь один раз предоставил через Android Storage Access Framework.
- Если Google Drive в Android умеет предоставлять права записи на дерево папок — его можно выбрать.
- Если Drive не предоставляет такую папку, автосохранение через SAF для этого провайдера **не работает**. Для настоящей прямой синхронизации нужен проект Google Cloud OAuth (client ID), согласие владельца Google-аккаунта и подключение Google Drive API. Секреты пользователя в репозитории не сохраняются.
- Локальное хранение базы всегда независимо от облака. Ошибка облачного архива отображается явно.
