# FARUKH PRINT — автоматическая проверка APK

## Что уже работает в коде версии 1.4.5-test (versionCode 12)

- При открытии приложения и после возвращения в приложение Android проверяет GitHub Release не чаще чем раз в 6 часов.
- Более новую версию скачивает в приватную папку cache/updates, автоматически проверяет её SHA-256, package name, versionCode и **цифровую подпись**.
- Если подпись совпала, не мешая печати, показывает диалог «Обновить».
- По нажатию «Обновить» запускается стандартный установщик Android. Android вправе запросить одноразовое разрешение «Установка из этого источника», а пользователь **всегда** подтверждает установку. Скрытая установка невозможна для обычного APK без системных полномочий.
- Если подпись отличается, программа **НЕ** предлагает удаление старой версии. Она сообщает об отличии и необходимости сначала экспортировать JSON-базу.

## Важный шаг владельца — стабильный ключ

Тестовый APK ранее собирался GitHub Actions с автоматически генерируемым debug-ключом. Поэтому более старые APK и будущие сборки могут иметь разные сертификаты и Android справедливо показывает «Несовместимо». Из APK извлечь закрытый ключ нельзя. Для нормального обновления необходимо **один раз** настроить постоянную подпись будущих APK.

**Никогда не загружать закрытый ключ, пароли или base64 keystore в открытый репозиторий или чат.** Хранить офлайн защищённую резервную копию: если ключ потерян, последующее обновление уже установленных версий окажется невозможным.

Шаги владельца репозитория:

1. На локальном компьютере с Java 17 создать собственный keystore, например:
   `keytool -genkeypair -v -keystore farukh-print-release.jks -alias farukhprint -keyalg RSA -keysize 3072 -validity 9125`
   (выбрать отдельный надёжный пароль).
2. Сконвертировать файл keystore в base64 **локально**. В PowerShell:
   `[Convert]::ToBase64String([IO.File]::ReadAllBytes("farukh-print-release.jks")) | Set-Content -NoNewline farukh-print-key-base64.txt`
3. В настройках репозитория GitHub **Settings → Secrets and variables → Actions → New repository secret** завести:
   - `FARUKH_PRINT_KEYSTORE_BASE64` — содержимое файла base64.
   - `FARUKH_PRINT_SIGNING_STORE_PASSWORD` — пароль keystore.
   - `FARUKH_PRINT_SIGNING_KEY_ALIAS` — `farukhprint`.
   - `FARUKH_PRINT_SIGNING_KEY_PASSWORD` — пароль ключа.
4. Запустить GitHub Actions → **Android FARUKH PRINT APK** → **Run workflow**. Релиз публикуется только при наличии **всех четырёх** секретов. Без них собирается лишь тестовый debug APK (не публикуется как обновление).
5. Проверить установку на отдельном устройстве и затем обновление следующей версии, подписанной тем же ключом.

## Однократная миграция со старой версии

Если установленная версия подписана другой (старой тестовой) подписью, Android не установит новую поверх неё. **До удаления** экспортировать и отдельно сохранить `JSON` из FARUKH PRINT, проверить, что файл реально существует и читается. Только после этого при необходимости удалить старую и установить первую версию с новым постоянным ключом, потом импортировать сохранённый JSON. После такой миграции будущие обновления с этим же ключом устанавливаются поверх приложения и данные сохраняются.

После каждого нового релиза увеличивать `versionCode` на 1. Обновления проверяются только при запущенном/открытом FARUKH PRINT; это не фоновый сервис, который будит спящий телефон.
