# FARRUH WORKSPACE PRO — один Android WebView для всех проектов

Отдельное Android-приложение с уникальным package ID `ai.farukh.workspace`.
Не заменяет установленный FARUKH AI, REVISION или PRINT. Исходные сайты/данные не удаляются.

Веб/PWA не может встраивать сайты с X-Frame-Options/CSP frame-ancestors (например FARRUH AI).
В APK ссылки на ВСЕ семь проектов открываются в ОДНОМ постоянном Android WebView:
все HTTPS-навигации остаются внутри приложения. Верхняя системная панель «‹ Проекты»
всегда возвращает в Workspace; Android «Назад» возвращает к предыдущей странице.

Приложение включает передачу выбора файлов, обычную загрузку HTTPS-файлов, 
Android Print / «Сохранить как PDF», камеру/микрофон по запросу проверенных доменов.
Никакого небезопасного addJavascriptInterface. HTTP заблокирован.

Ограничение: Bluetooth Web API может не поддерживаться Android WebView, проверка
V3 BT на физическом устройстве отдельно. Некоторые сторонние OAuth-провайдеры
не разрешают вход из WebView и могут требовать системный браузер.

Сборка: GitHub Actions → Build FARRUH WORKSPACE PRO Android →
artifact FARRUH-WORKSPACE-PRO-TEST-APK.

Это DEBUG-сборка, а не подписанный постоянным ключом релиз. Чтобы следующие нативные
APK ставились поверх старой версии, нужно хранить один постоянный RELEASE-ключ
защищённо в GitHub Actions Secrets. Не коммитить приватные ключи в репозиторий.
Изменения веб-сайтов внутри этого APK обновляются автоматически без установки APK.


## Обновления в самом приложении

Начиная с исходников Android 1.1.0, в нативной шапке есть кнопка **«Обновить»**. Она сразу обновляет веб-страницу, затем по HTTPS проверяет `/workspace-android-update.json`. Если найдена более новая **подписанная** APK с тем же `applicationId=ai.farukh.workspace`, показывает предложение скачать, проверяет SHA-256 и передаёт установку Android. Система может попросить разрешить установку из этого приложения и подтвердить установку — бесшумная установка стороннего APK без системного подтверждения недоступна.

**Тестовая APK от GitHub Actions не является релизом!** Она подписывается временным debug-ключом окружения сборки. Повторные сборки могут иметь другую подпись и не обновят ранее установленную debug-версию. Не обещать обновление debug через кнопку. Для релизного канала нужен постоянный production keystore, который **НЕ коммитится** в репозиторий; секреты `WORKSPACE_KEYSTORE_B64`, `WORKSPACE_STORE_PASS`, `WORKSPACE_KEY_ALIAS`, `WORKSPACE_KEY_PASS` должны храниться как секреты GitHub Actions. Впервые перейти с debug или другого package ID на такой релиз без удаления приложения Android может не позволить. Но после одноразовой установки одной релизной APK последующие релизы с этой же подписью и большим versionCode будут устанавливаться поверх.

Пока в JSON-манифесте `versionCode: 0`, нативная кнопка только обновляет веб-часть — **нет безопасной опубликованной подписанной версии APK**. Не публиковать туда временную debug APK.
